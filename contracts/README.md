# 桌面端、跨端同步与主题扩展约定

Android 0.1.0 已使用 Flutter 与原生 Kotlin 实现本地任务、日程和系统闹钟。Windows / macOS、认证服务与同步服务尚未接入。`types.ts` 是跨平台目标契约；已实现手机模型的字段与映射见 [mobile-v1.md](mobile-v1.md)。TypeScript 不约束最终实现语言。

## 数据与 UI 分离

1. 任务模板和每次发生的任务实例分离；完成一次每日任务不会完成整组任务。
2. 预计天数是规划信息；截止日期是独立字段。自然日、时区、跨午夜事件分别表达。
3. 截止日期变更用独立历史实体记录，包含旧日期、新日期、当时逾期天数和改期序号。逾期等级按当前截止日期与指定时区的本地日期计算，不从服务器缓存颜色。
4. 时间段使用明确的开始日期/时间和结束日期/时间，避免跨午夜歧义。相对提醒保存开始/结束锚点与带符号分钟偏移，不只存最终响铃时间。
5. 独立闹钟、循环排班和响铃样式分别保存；贪睡不混入周期规则。
6. 修改、删除、完成任务和同步远端变更后，平台调度器重新对账。已完成实例不生成提醒；恢复为未完成后按规则重新计算。一次性跳过和停止当前响铃是不同动作。

## Windows / macOS 适配

- 同一套业务模型、逾期算法、循环规则与主题语义供各端使用；平台层负责本机存储、系统通知、响铃、权限和开机后恢复。
- 手机以底部导航与单列详情为主；电脑以侧栏、内容区与详情栏为主。窗口变窄时收起详情栏。
- 时间规则需明确随设备当地时间还是固定时区；遇到夏令时缺失/重复时间，正式实现时要有一致策略和用例。
- 铃声采用逻辑资源 ID；平台本地解析路径。用户自定义铃声需要独立的素材同步与兼容性策略，不能同步本机绝对路径。
- 不把所有平台的后台/响铃能力视为相同；capabilities 和 reconcile 返回受阻原因，UI 可展示需要处理的系统设置。

## 同步流程

本地事务 → 本地待发送队列 → push（携带 baseRevision、mutationId）→ 服务端确认或冲突 → pull（增量 cursor）→ 本地事务应用 → 提醒调度对账。

- 所有实体使用稳定 ID，包含 schemaVersion、revision 与设备来源。重试复用 mutationId；游标只有成功应用后才推进。
- 删除使用 tombstone 传播；确认策略与保留周期由正式服务约定，避免离线设备把已删除任务重新创建。
- 客户端时间戳只作记录，不作为并发修改胜负的唯一依据。用服务端修订号检测并发。
- 并发编辑截止日期、完成与编辑冲突、编辑与删除冲突时保留双方版本；展示冲突选择，不能静默覆盖改期历史。
- 传输层、身份认证、账户/设备登记与本地存储分别设接口，可接自建服务或其他后端。当前未选定服务供应商。
- 凭证由平台安全存储提供，不写入任务数据、主题文件或日志。账户隔离与鉴权需在真实服务中实现。

## 哪台设备响铃

默认：Android 手机响铃，Windows 仅通知，macOS 静默。每台设备可分别设置 ring / notify / silent。

同一个提醒在同一台设备通过 occurrenceKey + deviceId 幂等登记。跨设备使用 primaryRingDeviceId 与离线回退策略；离线状态无法绝对保证跨端只响一次，必须向用户表达所选策略的取舍。完成任务的远端状态尚未同步到离线设备时，该设备仍可能响铃。

原型展示的是策略偏好，设备列表是示例设备，没有实际设备发现、注册或数据上传。

## 换肤扩展

ThemeDefinition 定义主题 ID、版本和明暗两套语义 token。业务模型只存状态与改期次数，不存 CSS 色值。UI 根据逾期等级、改期序号和主题把状态映射为显示颜色。

颜色、字族、圆角、间距、分隔线集中维护。ThemeProvider 管理主题加载与用户偏好；可选择偏好仅当前设备生效或随账户同步。新增皮肤不能改变七级深浅顺序，也不能去掉等级文字和改期次数。

HTML 原型通过 CSS 变量换肤；Android 通过 `mobile/lib/skins.dart` 中的 `SkinProvider` / `SkinTokens` 注入颜色与玻璃材质参数，通过 `appearance.layout` 切换三套布局。新增颜色皮肤无需修改任务、闹钟或同步逻辑。

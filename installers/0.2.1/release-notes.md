# 有期 Android 0.2.1：延后、关联提醒与常驻待办

日期：2026-10-12。versionCode 3，包名 `cn.youqi.youqi`，Android 8.0+，targetSdk 35。使用与 0.1.0/0.2.0 相同的测试签名，可覆盖安装，schemaVersion 1 不变。

## 用户反馈与定位

用户设备为红米 K90 Pro Max，HyperOS 3.0.310.0；已确认 10 秒测试与手动闹钟首次响铃正常，但点击延后 5 分钟后不再响，时间关联闹钟未出现。没有连接该手机的 ADB，因此以下代码缺陷能解释漏响路径，不能断言已排除手机的全部后台限制。

0.2.0 的日期计算和 5/10 分钟数值测试通过，但未覆盖原生调度、刷新与广播处理的竞争。本轮补充了原生集成回归，三个用例在旧调度实现上均失败，保留原报告 `mobile/reports/AlarmDelivery-before.xml`。

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 延后 5/10 分钟后漏响 | 对账只保留 `fireAt > 当前时间` 的临时提醒；广播线程处理前发生刷新就先删除记录 | 独立持久 deliveries 保存每次触发，保留未消费的到期记录 |
| 事件/循环提醒可能漏响 | 调度表按规则 key 保存一条记录，到期后先删除或替换为明天；广播再按 key 查不到本次 | PendingIntent 与广播携带 fireKey，读取本次不可变记录；本次与下一次可同时存在 |
| 重新打开仍无系统闹钟 | 本地记录未变就跳过 AlarmManager 登记；系统计时器被清除后不会自动恢复 | 每次对账幂等重新登记，同一 fireKey 替换原计时器，不产生重复 |
| 失败被当作已触发 | 启动前台服务之前先写入 fired，启动异常也永久消费记录 | 系统接受启动后才记录 fired；启动抛出异常保留记录并一分钟后重试 |
| 新增某天计划缺少原提醒 | 新时间段使用空提醒列表，覆盖该天模板规则 | 新时间段继承模板时间和提醒；可手动修改/删除，显式空列表仍保留为空 |

登记先落盘，广播处理、保存和对账共用同步锁。完成/删除任务、停用规则、修改时间、取消临时提醒后，旧记录与延后提醒均撤销；多个同时到达的事件逐一交付，响铃服务沿用排队处理与当前 fireKey 操作校验。

已登记但到期尚未处理的提醒保留 15 分钟补响窗口。超过窗口记录“错过提醒超过15分钟，未补响”，避免重新开机时播放很久以前的提醒。新建时提醒时间本身已经过去，不会倒推补响；设置界面显示相对提醒的实际时间，闹钟中心“已登记提醒”显示最多 20 条当前登记（每条规则的下一次及待处理记录），可手动刷新。

## 常驻待办通知

设置 → 通知栏常驻待办，默认关闭。开启后使用独立低优先级通知通道，无提示音与振动，显示未完成数量和最多 5 条标题；展开查看多行，剩余事项提示点击查看，全部完成时显示完成状态。包含此前保留到今天的未完成事项，与首页语义一致。点击打开 APP。

保存任务、完成/撤销完成、对账、启动恢复后刷新通知。关闭 APP 后安排午夜附近的非精确刷新，可补算尚未打开 APP 生成的重复任务；省电/休眠可能推迟这次静默汇总刷新，不影响精确闹钟通道。开关只存本机 SharedPreferences，不进入 outbox；未来桌面同步不会自动开启另一台设备的通知。

需要系统通知权限。Android 14+ 允许用户手动清除这类 ongoing 通知，常驻表示 APP 持续维护其状态，不能保证系统不允许滑掉。[Android 官方行为说明](https://developer.android.com/about/versions/14/behavior-changes-all#non-dismissable-notifications)。

三套布局、液态玻璃、滚轮及刻度震动沿用；SyncTransport、SkinProvider、稳定实体标识、增量队列和删除标记保留，尚未接入远程同步或桌面应用。
